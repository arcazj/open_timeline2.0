# ADR 0005: Committed Workspace Audit Chain

Status: implementation contract. This adds retain-all, metadata-only audit history; it does not claim complete checkpoint compaction or historical reconstruction.

Every new record, batch, visual-model, catalog or settings transaction appends one ordinary JSON document `audit/{revision:016d}.json` and replaces `audit-state.json` in the same PREPARED/COMMITTED journal as its records, workspace revision and command outcome. Failed preparation and rolled-back transactions produce no committed entry. The entry contains its revision, generation, timestamp, actor ID, command ID, coarse change family, safe record identity/version/source/deletion descriptors, visibility/owner scope, and the previous entry's SHA-256. Its own SHA-256 is computed over canonical repository JSON without the hash member. It contains no token, title, description, custom data or configuration definition.

Existing roots without audit history start at an explicit `firstRevision` equal to the next committed revision. Earlier revisions are not synthesized. The state identifies the first/last revisions, count, current generation and terminal hash. Every retained entry is validated at startup; missing, extra, malformed, nonconsecutive or broken-chain entries fail closed. Paths and raw byte admission remain bounded and link/reparse-point safe. No pruning is implemented. The chain provides integrity and ordering, not a cryptographic signature against an administrator who can rewrite all files.

An inactive backup restore retains all original audit bytes, appends a `workspace.restore` entry at the new workspace revision, links the prior terminal hash, names the prior generation and verified backup checksum, and updates state to the new generation. That is the only admitted generation transition inside a chain. A previously unaudited root starts a chain at its restore revision, explicitly preserving the earlier-history limitation. Restore actor is null because there is no authenticated HTTP actor; the offline operation's provenance identifies it.

Audit reads require `audit.read`. Records from unauthorized sources are never disclosed; an entry involving hidden sources is omitted as a whole. Personal configuration entries are visible only to their owner or an administrator. Shared catalog metadata requires unrestricted workspace source scope because legacy publications can contain cross-source references. Pagination is revision-ordered with opaque, principal/scope/generation-bound cursors; no hidden total count is exposed. Root identity audit remains separately governed by identity format 2.

Live invalidation may later consume this committed ledger, but audit existence alone does not implement SSE, asynchronous jobs, full data-version history or a compaction checkpoint. Those release requirements remain explicit.
