# Implementation Status

OpenBEXI Timeline 2.0 is undergoing full-release implementation. The revision 2.4 modernization specification remains the product target; the current candidate does **not** yet complete or certify all of its requirements. No requirement has been silently removed. The [release checklist](release-checklist.md) records the earlier baseline and outstanding package-level exit conditions; the additions below supersede its historical absence observations, not its unpassed gates.

## Implemented and Exercised

The [sorting/filtering and descriptor candidate](sorting-filtering/implementation-status.md) adds opt-in v2 safe regex, exact relationship/search provenance, natural ordering, typed group collapse, application-owned legacy preferences, reviewed migration, and automatic safe descriptor sidecars. Its focused evidence supersedes the older absence notes below; it does not close the full-release gates.

- One modular JavaScript application builds into a self-contained HTML file. Three.js, CSS, the font, icons and all 48 sample records are embedded. The generated file opens from a different local directory with HTTP requests blocked.
- A large orthographic detail timeline sits above a synchronized overview. Events, duration sessions, compact labels, translucent zones, selection and a right-side descriptor render from actual generic records.
- Navigation, overview range movement, manual zoom, uniform/adaptive maps and global vertical row pages share one time-mapping contract. Density is computed from the full filtered analysis range, not the loaded page.
- [Calendar and momentum navigation](calendar-navigation.md) adds longer frame-synchronized coasting, click-to-stop, continuing grids/overview outside the loaded range, and a right-side month/day picker. Hour selections default to 04:00 UTC; finer visible divisions expose finer time precision. The original date-range dialog remains available.
- Registered font metrics reserve marker, bar and label footprints. JavaScript and Python use matching measured allocation and Unicode search fixtures.
- Source/type filters, bounded typed filter trees, and contextual Any/All/Phrase search are implemented with case and field selection. Matching labels are yellow; the overview contains findings across the analysis range, including records on other row pages. Missing/null semantics and Unicode casefolding match across providers.
- Timeline, Table and Split views share selection but have independent pagination. Table queries sort the complete filtered set or an explicit time window; findings are a separate projection. CSV export traverses the complete chosen scope, not only the visible page. A selected record can be located on its timeline row page.
- Local records can be created, edited, duplicated and soft-deleted in memory. Complete JSON export and strict import preserve the local data source; import rejects duplicate keys and incomplete query-page envelopes. Downloads are requests, not proof of durable file saving.
- Python serves authenticated query sessions, density/maps, overview, zones, placements, pages, complete exports and basic event/session CRUD. Persisted data and transaction state use JSON files only, with one writer per root.
- Record versions, generation checks and idempotent outcomes are exercised in focused tests. The v2 JSON transaction protocol rolls back PREPARED work and redoes COMMITTED work after process interruption. Complete replacement PUT, bounded RFC 6902 PATCH, typed event/session routes, body-free DELETE and atomic mixed record batches share current authorization and one workspace commit. Server data is never silently treated as a complete local cache.
- Connection is explicit, compared before switching and bounded by timeouts. Outages select a complete local source with a visible warning. Reconnection never automatically uploads local changes.
- Optional [read-only legacy sources](legacy-json-sources.md) load enabled JSON-file entries from legacy YAML, including explicitly mapped `yyyy/mm/dd` archives. Full bounded scans build an overlap index, so earlier-folder sessions remain visible across day, month and year boundaries. Original JSON, descriptors, models and YAML are never rewritten; unsupported active source semantics and incomplete scans are rejected explicitly.
- The named legacy adapter preserves namespaces, nested activities, original dates and provenance, with an explicit compatibility dialect for observed non-strict JSON. Supported two-band model properties and source backgrounds render in the same client. [Actual production and standalone captures](legacy-json-preview.md) document the implemented result; they do not certify every historical model. Frame-synchronized drag previews, bounded inertia and reduced-motion behavior have focused browser coverage.
- Opt-in [local server paths](local-source-paths.md) support same-origin, loopback-only browsing without entering a token. Python advertises its approved read-only paths; the browser supports multiple selections and persistent favorite shortcuts. ALL/NAMESPACE switches grouping without rewriting legacy models. Navigation crosses query/archive edges within years 0001-9999, with a following overview and pinned drag geometry. Dense namespaces still use global vertical pages; independent per-namespace pagination is not implemented.
- The [earthquake/volcano comparison](hazard-rendering-parity.md) adds original embedded hazard icons, main-band quarter-hour subdivisions, measured Latin Extended place names and collision-free row reuse for unrelated point events. The 383-record range snapshot remains distinct from the full read-only archive; screenshots and test receipts state their exact scope.
- A versioned visual-model catalog works through both providers: create/duplicate, metadata and draft editing, common structured/JSON validation, isolated preview, definition diff, immutable publication, explicit version application, archive/unarchive, reference-safe deletion and portable definition import/export. Complete snapshots preserve catalog history and pins.
- Supported model definitions expose appearance, measured row/font sizes, grouping, all 11 display units, named time zones and adaptive/uniform scale settings. The named-zone registry and definition schemas are shared across languages. Record editing remains explicitly UTC.
- Optional versioned presentation definitions add separate band palettes, axis positions and date formats, source colors, typed custom grouping, label/inspector field selection, measured bold/italic fonts, multiline labels, approved record icons, original-time baselines and nested-session enclosures with explicit page continuation. All geometry is measured before globally assigning rows; older nine-field definitions retain their geometry path.
- Preview layouts follow viewport changes without replacing their immutable query/map. Uncertain server model-command identifiers survive reload without persisting tokens, payloads or private definitions; unresolved outcomes keep mutation controls locked. Record command intents are captured before queuing, and workspace/record revision capacity is enforced before mutation.
- The source-backed [legacy compatibility inventory](legacy-compatibility-matrix.md) enumerates 241 feature IDs, including listener branches, both allocation methods, model keys, menus and all legacy date formats. It distinguishes implemented behavior from migration and release gaps.
- Adaptive tick refinement selects finer calendar divisions in magnified intervals from the same pinned map used by records, zones and pagination. Temporal places actual calendar ticks, including daylight-saving transitions; approximate durations only choose an interval.
- A classic Blob Worker, embedded in the standalone file, runs the same Local provider for JSON parsing, validation, filtering, layout and export. Startup-only direct fallback is supported; a stopped worker never silently restarts from stale data. A 25,000-record offline test checks main-thread heartbeats and complete table traversal.
- Exact first-compatible-row allocation uses a bounded range index for larger groups without changing record order or clearance rules. Query-local time bounds and bin-range counts avoid repeated overview scans. Performance measurements are recorded separately from correctness tests.
- Python snapshot integrity verification/export now uses RFC 8785 canonical bytes. Differential tests verify JavaScript agreement on model histories, numeric keys, non-BMP Unicode keys and fractional numbers. Hashes detect content changes; they do not prove source identity or replace authorization.
- Shared schemas use JSON Schema 2020-12. Published custom-schema pins validate record data and drive matching typed filter/sort fields. Sources, groups, schema histories, owned saved filters/views and layered effective settings work through both providers and the configuration manager; complete snapshots retain their dependency closure.
- The Python identity root provides scoped viewer/editor/admin principals, hashed expiring tokens, versioned/idempotent administration and explicit local recovery. Source authorization occurs before counts, density and layout. Query/outcome ownership is checked again against current credentials. Identity administration is Server-only.
- Workspace commits append a checksummed audit chain in the same JSON transaction. Authorized audit pagination and polling/SSE invalidations contain no private record payloads. Source moves to a hidden source can invalidate a view without revealing the destination or record identity.
- Complete offline backup/verification/restore and a live capture primitive preserve raw records, shards, catalog history, outcomes, identities and audit. Restoration changes generations, revokes every old token and requires explicit recovery before access. Process-exit, corruption, source-preservation and restart tests are included; a tracked-job API and retention compaction remain separate work.
- Optional ordinary-JSON shards and an inactive-root migration tool reduce file overhead without skipping full startup validation. Layout 1 remains readable; migration preserves the source and refuses uncertain transactions. Measurements are not a cross-platform performance qualification.
- Native OpenAPI 3.1.1 schemas cover registered routes, problems, preconditions and response headers. Export is deterministic and tested against a vendored specification schema. Health/readiness/capability endpoints distinguish liveness from safe storage availability.
- A rolling, bounded integrity monitor checks admitted JSON authority, including same-size/same-timestamp changes and missing outcomes or journals. Detected external changes freeze repository availability. Windows observation/commit coordination and joined shutdown have regressions; their latency and broader filesystem qualification remain measured separately.
- Authorization changes invalidate affected retained query artifacts before administration returns; token expiry and identity-file drift are monitored. Name-only edits do not unnecessarily discard queries. Client revocation handling clears records and protected source/model/count metadata without silently switching to Local.
- The Python query coordinator owns bounded preparation workers/queue, ready/preparing/failed status, cooperative cancellation and deadline handling. Immutable snapshot capture uses copy-on-write record references; query/layout/table artifacts share measured graph accounting. Cached table pages avoid new preparation permits. The first 100k admission diagnostic remains too slow for the initial-status target.
- Server Pinned/Live controls preserve coherent rows/maps/counts/overview. Pinned changes are notice-only until Reload; Live coalesces changes and defers replacement during active gestures and drafts. Explicit record time edits use captured source/generation/version and a fixed gesture map; navigation never writes records. Full geometry hysteresis and all legacy interaction variants remain open.
- The standalone build embeds full runtime dependency/font/Unicode notices and records their inputs in its build manifest. Candidate verification records immutable test evidence and refuses to treat missing, empty, skipped or failed reports as a pass. A Linux verification image and a nonpublishing Windows/Linux CI workflow are included; availability is not evidence that every matrix run passed.

## Limits That Remain

These are follow-on implementation tasks, not features to delete from the prompt:

1. Close the remaining implementation rows in the legacy inventory. Inventory coverage is not runtime compatibility certification, and original artifacts remain authoritative. Unsupported migration semantics produce explicit diagnostics rather than being silently discarded.
2. Complete workspace administration, the full model/reference-upgrade graph and dependency-aware legacy migration. Catalog/schema/filter/source authoring now exists, but that does not close every resource or migration clause. Additional detail bands, broader approved assets/fonts, optional source-backed camera compatibility and legacy fixed geometry/spacing still need implementation; the default remains orthographic.
3. Add large-overview drill-down, footprint-only context and oversized-page fragmentation; finish preparation latency/resource qualification. Authorized ancestor context and typed group collapse now work in the version-2 workflow; all navigation variants are not certified.
4. Complete remaining interaction/accessibility variants and broader registered fonts/glyphs. Full historical/calendar behavior across all browser time-zone databases is not certified.
5. Certify the full large-dataset performance/resource budgets. Shard startup has improved in exploratory measurements, but the required controlled cold/warm distributions and concurrency/RSS evidence remain absent. Worker-denied Local execution is not yet cooperatively sliced throughout all algorithms. Limits reject unsupported sizes rather than silently dropping data.
6. Complete adaptive geometry hysteresis/provenance, live timing qualification, conflict comparison/reapply, conditional undo/redo, trash/bulk workflows, field-level permission contracts, tracked import/backup jobs, retention/checkpoint policy and deployment hardening. Scoped authorization, atomic batches, backup primitives and reload-safe record/model/configuration recovery are implemented, not replacements for these remaining clauses.
7. Complete the release integrity-validation matrix and backup/provenance qualification. Canonical hashes and known-dependency audits are not a complete security audit. Process-interruption tests do not certify power-loss or filesystem durability guarantees.
8. Run the full documented G0-G5 release gates, cross-browser/platform matrix and evidence requirements. The current Windows/Edge tests are incremental implementation evidence, not release certification.
