## Disposition rules

`Preserve` means retain the requirement or demonstrated visual meaning. `Correct` means retain its intent while explicitly resolving an ambiguity, unsafe behavior, or conflict with a newer user constraint. `Exclude` applies only to behavior overridden by the user's scope or safety requirements. `Covered`, `Partial`, and `Missing/conflicting` describe Revision 2.1 text coverage; they are not application test results.

## Mandatory reconciliation summary

The largest Revision 2.1 omission is the complete illustrated visual contract on pages 8-17, not a few missing colors. Revision 2.2 must replace the default dashboard-like workspace with the compact blue legacy composition, preserve alternate model styles, introduce the right calendar and independent reference marker, implement the exact grouped Table and responsive Split contracts, and use the 14-record fixture consistently across the new primary mockups.

The narrower nonvisual additions are complete first-party source reading, explicit read-only source policy, documented preference/link-state scope, fixed fixture seeds, formatting/lint/type/static checks and CI, contribution guidance, and the named UI specification/visual evidence deliverables.

No model family may be dropped because its appearance differs from the blue default. The existing all-model compatibility, source-consumed property coverage, secure descriptor replacement, JSON-only storage, CRUD, versioning, import, synchronization, and recovery requirements remain in force.

## Ambiguities and deliberate resolutions

1. **Pixels versus data:** Figures 3-5 visibly contain illustrative bar placements and extra decorative overview marks. Page 12 explicitly makes exact geometry and the final fixture authoritative. Generate the replacement from timestamps and exactly 14 records, not by tracing those accidental marks.
2. **Canonical IDs:** `EVT-001` through `EVT-014` are human-readable fixture aliases. Preserve them in a declared metadata/identity mapping while the application's canonical identity remains its UUID. The visible ID column may display the alias when its meaning is explicit.
3. **Domain indicator:** The fixture's Indicator values are synthetic persisted metadata. Bind them explicitly through a fixture adapter, such as declared `data.status`, and keep selection/focus separate. Never change Nominal to Selected.
4. **Reference versus Now:** The fixed reference/playhead is 15:00 UTC. The PDF does not assign a different live clock instant. Freeze the clock explicitly for each test; add a separate test where Now differs. Neither selecting a record nor a metadata indicator automatically moves the reference marker.
5. **Scope:** Current range is the preferred legacy model's explicit initial scope, not a hidden global filter added to every API request. All matching remains a clearly different scope.
6. **Date boundaries:** Apply the main canonical half-open semantics, including the special point/zero-duration rules. Preserve incompatible historical input meaning through explicit adapters; do not reintroduce ambiguous boundary behavior silently.
7. **Exact dimensions:** The numerical desktop geometry applies at 1600 x 900/100% zoom. Responsive layouts, long data and accessibility must follow the declared breakpoints and overflow behavior. Comfortable and compact density have different body extents.
8. **Table arithmetic:** The legacy width sum is correct: 44 + 112 + 92 + 440 + 148 + 148 + 132 + 188 = 1304. Event remains 440 px. No documented arithmetic correction is needed.
9. **Operational support:** The broad brief's database/protocol optionality, optional API documentation and immediate implementation wording are overridden by the user's JSON-only, complete API and prompt-only constraints.
10. **Visual proof:** Proposed screenshots, repository screenshots and eventual application screenshots are separate evidence categories. Keep their labels and attribution distinct, and do not claim all models or gestures passed from an image comparison.
