# Provider and Standalone Contract

## 1. Scope and Precedence

This is a prompt-only specification, not implemented software or passing test evidence. The backend is Python, not Java/Tomcat. The frontend is modular JavaScript using Three.js for its 2D timeline; a build step produces both the served frontend and one self-contained, directly openable HTML artifact. Runtime use of that artifact requires no Python, Node, installation, CDN, network, or local server.

Both modes retain timeline/table views, models and field catalogs, search, filters/grouping, adaptive scales, overview, annotations, selection/details, vertical pagination, record/configuration editing and JSON import/export. Differences concern authority, durability, supported capacity and server administration, not placeholder feature buttons. Use generic UI terminology and configurable themes, rather than requiring a named historical interface. The existing [adaptive query](adaptive-query-contract.md) and [scale](adaptive-scale-contract.md) contracts apply through the active provider; this contract overrides their previously server-exclusive assumptions.

## 2. Shared Asynchronous Interface

Renderers and controllers depend on one provider interface, never direct HTTP, filesystem operations, an embedded global event array, or separate mode-specific UI implementations. `ServerProvider` translates it to the Python REST API; `LocalProvider` implements it over a complete admitted in-memory snapshot. Every operation returns a promise, accepts cancellation and a monotonic client intent ID, and returns provider identity/epoch, query identities, completeness and structured errors. Cancellation is best-effort; obsolete responses cannot activate.

| Interface operation | Shared contract |
| --- | --- |
| `initialize`, `getCapabilities`, `getStatus`, `dispose` | Establish identity, capacity, authority/durability and supported commands; release provider requests, workers, object URLs and handles. The renderer, not the provider, owns GPU resources. |
| `createQuery`, `getQuery`, `releaseQuery` | Pin C/M, scope, versions and domain; ready/preparing/failed lifecycle. |
| `getDensity`, `getMap`, `getOverview`, `getZones` | Complete-scope statistics, authoritative map, bounded overview/annotation pages; no inference from loaded detail. |
| `createLayout`, `getLayout`, `releaseLayout`, `getRows` | Global profile-aware allocation; height/row/byte bounds, payload fragments and stable cursors. |
| `getPlacement`, `getRecord`, `queryRecords` | Explicit reveal, complete authorized details, and paginated table/query results. |
| `getCatalog`, `getFieldValues`, `getEffectiveSettings` | Typed scoped fields, distinct values and resolved model/settings provenance. |
| `listResources`, `getResource`, `executeCommand`, `getCommandOutcome` | Models/schemas/versions/drafts, sources/groups, filters/views/settings and record commands with shared validation/reference rules; outcome lookup is read-only. |
| `prepareImport`, `commitImport`, `prepareExport`, `getExport`, `cancelOperation` | Stage/validate, obtain impact and commit explicitly; expose format, scope, completeness and progress. |
| `subscribeChanges`, `compareSource` | Server change stream/polling or local committed-memory notifications; read-only reconnect comparison, never synchronization. |

Commands carry operation/resource type, payload, expected version, provider epoch and client command ID. Results declare `durability: server-committed` or `memory-only`. Server commands retain their client/retry identity under the durable protocol. `GET B/command-results/{clientCommandId}` provides authorized, origin-scoped status without executing a command. Server ETags/generations are never local concurrency tokens. Local mutations serialize, validate a whole bounded command/batch before changing memory, advance a separate local epoch/revision, and retain in-memory retry identity. Reload loses that state. Existing schema limits, 500-record/8-MiB batches, search grammar, reference safety and version conflicts apply in both modes. No local command claims crash recovery, journal durability or filesystem commit.

Real server-only capabilities include identity/token administration, server-root/bind/security settings, durable backup/restore, process health/recovery controls and remote notifications. Local UI shows these as unavailable with a concise reason or omits irrelevant controls. It must not simulate successful server administration. Local model publication, reference updates and source policy management operate on the local working copy and remain exportable.

## 3. Complete Portable Snapshot

Define a versioned `timeline-snapshot` JSON envelope containing format/schema versions, bundle ID, creation time, origin workspace/generation/revision, declared export universe, capabilities/provenance, data and asset manifests. Server export defaults to all records authorized for the explicitly declared workspace or source set at one snapshot. It is not the current search, time window, table page or row range. A source-limited export identifies that limitation visibly; it is not represented as the whole server workspace.

Include canonical records and required relationship closure, schemas/definition versions, selected models/drafts, sources/policies, groups, filters/views/settings, approved assets and font/render profiles. Include every runtime dependency or fail safely; never leak an unauthorized dependency. Secrets, tokens, private paths, process configuration, password hashes and identity-management data are excluded. Origin actor/owner IDs remain provenance, not runtime principal dependencies; local mutations use a local actor identity rather than impersonating server actors. Only authorized portable preferences are included. Deleted-record retention is explicit; an ordinary snapshot is not a server disaster-recovery backup.

The manifest lists each member's type/ID, byte length and SHA-256, asset MIME type, record/definition counts, complete ID inventories or their defined digest, and `completeness: complete-for-declared-universe`. Hash structured members as UTF-8 using [RFC 8785 JCS](https://www.rfc-editor.org/info/rfc8785/); hash assets as decoded bytes. Preserve original string code points for storage/hashes; search normalization is comparison-only. An explicit export capability and user action authorize creating a portable copy. Checksums detect corruption, not authorship, authenticity or continuing server permission. An exported file cannot reliably be revoked remotely.

Validate before activation: strict UTF-8/JSON, supported versions, sizes, duplicate property names/IDs, checksums/counts, timestamps/types, acyclic parents, source consistency, references, fields/styles, assets and URI forms. Reject NaN/Infinity and lone surrogate escapes rather than accepting a runtime parser's permissive defaults. Missing pages/dependencies or unsupported mandatory features reject the candidate. A large count or terminal cursor alone does not prove completeness. Never prototype-merge imported objects or execute strings. Keep the prior working copy intact on failure/cancellation; report safe path-based diagnostics.

The Python exporter derives inventory/counts from one authoritative authorized snapshot and verifies emitted membership before completion. Offline structural/hash checks establish internal completeness, not proof that an untrusted author included everything once held on a server; mark unverified imported origin claims accordingly. The portable format is one independently parseable JSON document with embedded assets. Local JSON export includes its complete admitted universe/references and edits/new IDs/deletions. CSV and selected-record exports are explicitly incomplete convenience subsets, ineligible as automatic fallback snapshots.

## 4. Local Authority and Capacity

The delivered standalone artifact contains a complete validated generic embedded snapshot as its default local source and startup/outage fallback, clearly identified as a sample rather than server data. A user-selected complete import may replace that fallback; creating an explicitly empty workspace is also available. Fallback is mandatory, not a deferred optional feature. Local working state has an independent epoch and retained origin metadata, not a writable server cache. New local records receive new UUIDs; imported server identity/version is provenance, not overwrite permission.

Edits, undo/redo, model drafts, policies and preferences remain in RAM. Show Modified in memory and Export JSON. Export prepares a validated snapshot and requests a download; it never overwrites the opened HTML/source JSON. Do not require File System Access, IndexedDB, localStorage, service workers or browser databases. Ordinary downloads cannot reliably confirm destination writes or cancellation: report Prepared/Download requested, not Saved. Do not clear modification state merely on a download click; user confirmation or reimport/hash verification can establish preservation of that revision. Reload warnings are best-effort. No automatic upload or reconciliation exists.

Honor read-only source policy in local controls; making an editable local copy is an explicit local configuration action retaining provenance. Local capability flags guide behavior but cannot secure a file against its owner modifying it. The server rechecks all authorization and policy if any future explicit import is requested; it never trusts local capability assertions, versions or checksums as authorization.

Initial Local capacity is 25,000 records, 64 MiB total decoded bundle data including at most 32 MiB approved assets, 128 MiB query/layout working admission budget, two query sessions, two layouts per session, one active preparation and queue capacity eight. Common density/map bounds, 50/100-row ceilings, 1,000 projections/2 MiB per response and eight fragments per logical page remain unchanged. These are declared support limits, not proof of an exact browser-heap bound; measure peak heap separately. Exceeding a limit rejects the whole candidate or operation, never truncates the dataset. Increasing a supported limit requires equivalent benchmarks. Server mode retains its independent larger reference tier and budgets.

## 5. Single-File Build and Execution

Maintain frontend modules in source; bundle all runtime JavaScript, Three.js/add-ons, query/layout logic, validators and approved libraries into a classic IIFE-compatible inline build. Embed CSS, fonts, icons/textures, worker source and JSON. No runtime imports, source-relative asset fetches, CDN links, sibling files, module-loader server assumptions or service-worker bootstrap may be necessary. The artifact must work after copying only that HTML file to another directory and opening its `file://` URL with networking blocked.

Embed JSON as inert data, with safe serialization of HTML-sensitive characters including `<`; parse text using the validated JSON path, never `eval`, `Function`, injected HTML or executable template strings. User labels remain text. Imported SVG/HTML/script and external font/asset references are rejected or transformed through a separately approved safe asset adapter, not fetched opportunistically. Use self-contained approved image/font bytes and revoke temporary object URLs on disposal.

Prefer a worker created from bundled source in a Blob URL, with no worker imports. Feature-detect worker/canvas/font support. If unavailable, use a tested cooperative main-thread path with an eight-millisecond work-slice budget, cancellation at slice boundaries and progress. Large parsing/validation requires an established incremental parser or equivalent bounded strategy, not one unbounded blocking loop. Worker failure cannot become a permanent loading screen. The fallback passes the same semantics, though its declared performance tier may be lower.

Implementation status, not a waiver of that target: the current client embeds the same LocalProvider in a classic Blob worker and has a functional direct-provider startup fallback. The direct path is not yet cooperatively sliced and can block on large inputs; the eight-millisecond fallback/cancellation budget remains an unresolved release requirement. See [standalone mode](standalone-mode.md) for implemented worker failure, explicit import and uncertain-write behavior. A successful worker or worker-denied functional test does not certify that remaining performance target.

Default pure Local launch makes zero network requests. A Python-served build and a file artifact with a configured, user-approved server endpoint can also use ServerProvider. Cross-origin connection is explicit; a Python server may opt into authenticated file-origin access, but `Origin: null` is never trusted identity. Require bearer authorization and preflighted mutation headers, no ambient-cookie trust and no permissive origin bypass. A rejected cross-origin connection leaves Local usable.

## 6. Startup, Outage and Reconnect

Use explicit source/connection states: Local ready/modified, Server probing/ready/stale, Authentication required, Candidate validating, Switching and Error. Connection errors can coexist with a usable separate Local source. Display source/origin, completeness and memory-versus-server durability. Keep Local usable while an optional configured server probe runs; its two-second deadline is independent of slower candidate validation. After interaction/edits, probe success offers Switch to server rather than changing source underneath the user.

Server outage means transport failure or explicit unavailable response, not every non-200 result. A 401/403 requires authentication/permission handling; clear affected managed content and never automatically downgrade. Other application errors retain their meaning. Genuine outage activates the configured complete local fallback, announces its distinct source/coverage and preserves compatible view state; the shipped generic snapshot supplies the default, or the user's validated complete import replaces it. Never portray it as cached server truth. Server row pages cannot become LocalProvider data. If the configured bundle itself fails validation, show Retry/Import/new-empty choices, not fabricated complete server data.

Provider switching stages validation, query/map/layout and the first complete visible page, then atomically activates one epoch. Empty/preparing/stale states stay explicit; old responses/handles cannot update the new source. Account for both candidates. The source coordinator detaches old scene resources before provider URLs/handles are released; GPU disposal stays renderer-owned. A lost server reply remains outcome-unknown, never locally confirmed. Read-only status reports pending/committed/failed/not-found/expired-unknown; not-found cannot prove an in-flight request will never arrive. Reconnect may look up status, but retrying the original key requires an explicit user command because it could create a previously uncommitted write.

Reconnect compares provider identity, origin generation/revision, declared scopes and local new/edited/deleted counts. Different authorization/export universes are not evidence of deletions. It performs no uploads. Offer Stay local, Export local JSON, or Switch to server after an explicit keep/export/discard decision for volatile edits. Switching queries current server state independently; it does not replay local commands or turn local versions into server ETags. Any later user-requested server import is a separate reviewed, authorized, version-checked operation with impact preview, not background synchronization.

## 7. Python/JavaScript Parity

Share machine-readable schemas, algorithms and deterministic fixtures. Python owns server domain/storage/API modules; JavaScript owns local implementations and shared controllers. Validate strict JSON types before domain processing; do not let Python/Pydantic or JavaScript silently coerce strings/booleans into numbers/dates. Named legacy adapters remain explicit. No browser Python runtime, divergent filter language or renderer bypass of provider pagination is permitted.

- Dates: accept only the strict offset/Z timestamp contract, years 0001-9999 and integer milliseconds. Reject ambiguous parsing, leap seconds and excess precision. Use epoch arithmetic and validated calendar rules, not locale-dependent parsing. Test every supported scale unit from milliseconds through millennia, UTC/IANA formatting and DST boundaries with a pinned timezone-data policy; disclose mismatches rather than silently changing instants.
- Strings/search: pin Unicode 15.1 normalization/full case-fold tables from the [Unicode Character Database](https://www.unicode.org/reports/tr44/) in both runtimes. Caseless comparison is `NFC(fullCaseFold(NFC(text)))` using default, not Turkic-specific mappings. Count title/search bounds in original Unicode code points before fold expansion; test astral characters. Apply identical Any/All/Phrase quoting/escaping and 512-character/20-term limits. Default string sorting compares NFC strings by code point, case-sensitive; explicit null then missing follow present values in either direction, and final ID ties are ascending. Reject mixed nonnull types. JCS property ordering separately follows its specification.
- Numbers: core integers, versions and ordering keys stay in the JavaScript safe-integer range; reject unsupported input instead of rounding. Numeric custom fields use finite binary64 semantics. Exact aggregate overlap-millisecond sums may exceed that range: compute with arbitrary-precision integers internally and serialize defined decimal strings when necessary. Counts and membership must match exactly.
- Maps: deterministic record/endpoint reduction order and the same density formula produce equal count components and tolerance-equivalent floating results. Do not demand identical `log1p` bit patterns across runtimes. Test forward/inverse invariants and projected positions within the scale contract's tolerances; never quantize knots so quiet intervals collapse. Provider-scoped map IDs may differ while semantic inputs and geometry agree.
- Layout: registered profile/font hashes, labels, ordering, dimensions and clearance rules match. Server measurement cannot trust arbitrary uploaded widths; LocalProvider can measure its complete admitted snapshot using bundled fonts. If shaping differs across supported engines, identify different profiles/layout IDs and test collision-free readable results rather than pretending identical row breaks. Exact row membership/cursors are reproducible within one profile/provider; cross-provider ID sets/counts and time coordinates remain equivalent. A switch reanchors explicitly, never reuses foreign cursors.

## 8. Verification Gate

The [integration plan](integration-test-plan.md) must execute real Python API/JSON durability tests, JavaScript local-provider conformance, and file-open browser workflows before implementation is delivered as complete. Test copy-alone/network-blocked launch, denied Blob workers, imports with malicious strings/missing dependencies, resource limits, local CRUD/export/reimport, all scale units, full-scope density and row traversal, server startup delays, 401/403 versus outage, lost writes, reconnect without uploads, stale replies and source-switch cancellation.

Run identical fixtures through both providers; record exact semantic comparisons and declared geometry/profile tolerances. Verify checksums/counts after JSON export/reimport and unchanged source files after local edits. Benchmark Local at its admitted tier separately from Server. A two-second probe timeout or usable shell is not proof that a large imported dataset has finished validating/rendering. Report pass/fail/skip and unsupported browser cases honestly; these requirements have not been executed as application tests in this prompt-only revision.
