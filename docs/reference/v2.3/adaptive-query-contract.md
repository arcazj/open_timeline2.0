# Adaptive Timeline Query Contract

## Status and Authority

This proposed prompt-only contract contains no application code or runtime-test results. It complements the main prompt, [adaptive scale contract](adaptive-scale-contract.md), [menu/search audit](legacy-menu-search-audit.md), and [integration test plan](integration-test-plan.md). The scale contract owns mapping mathematics; this document owns server authority, bounded transfers and row pagination, extending existing JSON storage, authorization, snapshots and contextual search.

## One Immutable Query Session

Let `B` mean `/api/v1/workspaces/{workspaceId}` and `Q` mean `B/query-sessions/{queryId}`. A query session pins one workspace generation, committed revision, authorization-scope fingerprint, versioned filter/search definition, source/schema scope, effective visual-model versions, and finite overview/analysis domain `O`. Its authorized filtered canonical record set is `C`; independent search findings form `M`, a subset of `C`. Optional explicit time predicates constrain `C`; browser loading windows do not. Retain canonical IDs only once in counts, even when a model renders multiple instances.

Session creation uses the existing immutable query backing snapshot and retention budget, not a second snapshot pool. Reject partial or approximate preparation presented as complete. The manifest returns `queryId`, `snapshotId`, generation/revision, normalized scope/search, `baseTotal`, `matchTotal`, `overviewTotal`, `overviewMatchTotal`, `expiresAt`, model references, and a state of `preparing`, `ready`, or `failed`. Define `C_O`/`M_O` as records intersecting O and `C_W`/`M_W` as records intersecting the exact detail window W. Overview totals count C_O/M_O; layout `detailTotal`/`detailMatchTotal` count C_W/M_W; base/match totals count all C/M. Never call a loaded-page count one of these totals. Search overview uses M_O, not only M_W. Ancestor context and regions never enter these totals.

Authenticated creation/inspection/release are read-only with respect to canonical resources. They do not advance workspace revisions, create record audit mutations, persist search styles, or require the durable-write `If-Match`/`Idempotency-Key` protocol. Handle deletion is resource release, not canonical DELETE. Every use rechecks current authorization and generation. A client-generated `clientRequestId` deduplicates identical preparation requests in memory for the handle lifetime; changed content under that ID returns 409. Restart expires the handles rather than attempting durable retry replay.

## Routes and Bounds

| Route | Concrete behavior |
| --- | --- |
| `POST B/query-sessions` | Accept filter/search, schema/source scope, model versions, finite `O`, display zone and mode. Return 200 with a ready manifest, or 202 with handle/status Location while preparing. No event array is returned. |
| `GET Q` / `DELETE Q` | Inspect state/manifest or release an owned handle. Release is idempotent with 204 for an already released owned handle under the disclosure policy; subsequent result reads return explicit expiry. |
| `GET Q/density` | Return exact bounded statistics across all eligible records in `O`, for named projection `context` or `matches`. Return density ID, algorithm version, bin boundaries, counts/occupancy, totals and completeness. No row cursor parameter is accepted. |
| `GET Q/overview` | Return bounded aggregate cells or individual marks from the same snapshot/domain. Active search selects `M`; otherwise use `C`. Each aggregate identifies its predicate, count, interval and drill-down token. Paginated group slices remain explicit, not an incomplete global overview disguised as complete. |
| `POST Q/layouts` | Prepare a layout using a map ID or mapping parameters; typed range or mapped coordinates; CSS width/height budget and reserved-space measurements; grouping/expansion, camera and registered render profile. Reject conflicting representations. Return 200 or 202 with immutable `layoutId`, `mapId`, row totals and status Location. |
| `GET Q/maps/{mapId}` | Return the immutable map manifest and validated knots for this query, including any declared retained-geometry lineage. Never serve another snapshot's map under this identity. |
| `GET Q/layouts/{layoutId}` / `DELETE Q/layouts/{layoutId}` | Inspect readiness or release layout resources without releasing shared query backing data still in use. |
| `GET Q/layouts/{layoutId}/rows` | Read a height-fitting complete row prefix under the declared row ceiling, or resume its opaque cursor. The endpoint never infers a later time window from the next page. |
| `GET Q/layouts/{layoutId}/placement/{recordId}` | Return authorized render-instance/row locations and a row cursor for explicit reveal. Return an explicit outside-layout result for an authorized record outside this layout; do not move time implicitly. |
| `GET Q/zones` | Return paginated authorized region annotations, with stable IDs, scope and canonical boundaries, independently of record counts. Both bands clip/project these using their declared transforms. |

Proposed first-release limits are deliberately finite:

| Resource | Default / ceiling |
| --- | --- |
| Session lifetime and retained data | Five minutes; four sessions per principal; 256 MiB global retained query/layout working budget, shared backing where safe. No automatic eviction of promised live handles. |
| Layouts | Two retained layouts per session, including preparation; explicitly release superseded ones. Preparation counts against memory admission. |
| Plot width | Integer CSS width 128-8,192; validate finite camera/view parameters and profile-approved font sizes before allocation. Device pixel ratio does not multiply logical row coordinates. |
| Data-height budget | 32-8,192 CSS px after fixed reservations; reject nonfinite, inconsistent or insufficient budgets. Height is not permission to shrink fonts. |
| Density/map | 128 requested bins, selectable 16-256; effective count and at most 256 positive-slope segments follow the scale contract; maximum slope ratio 8:1. |
| Row request | 50 logical rows by default, maximum 100; at most 1,000 record projections and 2 MiB uncompressed JSON per response. |
| Overview / zones | At most 1,000 marks or aggregate cells and 2 MiB per response; zones 128 per page, maximum 512. Group/annotation continuation is explicit. |
| Preparation input and work | 64 KiB request; one active preparation per principal, two globally, queue capacity eight. A preparation exceeding 30 seconds fails explicitly and releases reservations. |
| Render projection | At most 16 KiB per item; bounded labels and approved assets/styles only, not the complete 256 KiB canonical record. Full authorized fields remain available through the record/inspector API. |

Capabilities advertise configured limits. The query manifest tracks bounded per-artifact ready/preparing/failed states; an unprepared density or overview request returns 202 with its status reference, never fabricated empty statistics. Admission reserves memory for the complete promised result or rejects with 429 and Retry-After. Budget pressure must not produce a sampled density or silently drop late rows. The server may scan all matching IDs and perform bounded server work; the browser must not fetch all records or all labels to construct a page.

## Density and Shared Maps

Compute density over every canonical record in the requested projection intersecting `O`, including long sessions beginning before `O` and ongoing sessions extending through its end. The companion scale contract defines point/zero-duration counts, overlap occupancy, true finite endpoints and half-open boundaries. Return integer count components and duration-derived occupancy separately so clients do not mislabel occupancy as a unique record count. Summing per-bin overlap counts is not a valid global total.

The server creates authoritative, strictly increasing normalized knots over fixed `O`. The map manifest contains `mapId`, `densityId`, `algorithmVersion`, projection, snapshot identity, `O`, parameters and knots `{timeMs,u}`. Hash semantic input and knots into the ID. Hysteresis/interaction retention additionally declares fresh candidate hash, `geometryHash`, `retainedGeometryFrom`, decision and deadline; a fresh snapshot requires a fresh map identity even if knots are retained. Contextual search uses full `C` density, so changing only yellow highlights cannot rearrange contextual detail; an explicit matches-only layout uses `M` and therefore receives a different layout/map identity. Ordinary search overview still renders only `M`.

The main band views mapped coordinates `[a,b]`. Its exact visible time bounds come from the continuous inverse; an integer-millisecond `fetchWindow` is only a conservative server retrieval envelope. Membership, clipping and counts use the exact visible bounds, not that envelope. Fractional-millisecond view coordinates never become canonical timestamps. Typed ranges retain exact millisecond endpoints. Current range is a W display projection; it does not rewrite C's fixed authored predicates on every pan. The overview remains linear over `O`, showing the inverse-derived detail interval. Horizontal navigation inside `O` changes `[a,b]` and layout, not the map; vertical pages change neither. At O's boundary, clamp rather than extrapolate; extending O rebases query, density, map, overview and layout atomically. Changed mapping parameters or scope also create new identities.

Overview groups and density drill-down use server tokens bound to the same projection/revision. A drill-down is a new explicit predicate, not permission to fetch excluded records. Regions, label lengths, row counts and whichever page happens to be loaded do not affect temporal density.

## Global Rows and Trusted Footprints

Layout preparation examines the complete eligible projection, not one record page. Resolve labels, styles, icons, baselines, nesting and groups server-side. Select records by canonical overlap plus conservative projected-footprint candidates: a label or baseline entering the viewport may require an otherwise offscreen record. Flag `footprintOnly` instances and exclude them from time-window totals. They must still satisfy C (or explicit M projection); never bypass authorization/filters. Ancestor context is separately flagged. Neither context type adds overview marks/density; search overview stays exactly M_O. A start-date-folder scan is insufficient.

A registered `renderProfileId` identifies approved local font-file hashes, font selection, shaping/measurement engine version, size/weight/style rules, wrapping/overflow policy, icon dimensions, outline/padding and camera transforms. Use an established shaping/rendering engine with the same approved fonts as the client. Measure resolved text, not character-count guesses or a browser-submitted width for an untrusted record. Cache measurements by complete text/style/profile hash. The client waits for fonts/assets and validates actual bounds; a mismatch beyond 0.5 CSS px blocks the claimed collision-free layout and requests a corrected profile/layout, never a silent local repack. Unsupported fonts require a disclosed approved fallback or activation diagnostic.

Reserve the full footprint, including the largest enabled search/selection/focus decoration, so transient highlighting does not renumber rows. Maintain at least 4 CSS px clearance between unrelated footprints. Labels longer than available width use the declared expanded/multiline/ellipsis policy with accessible full text; projection-size limits cannot silently change canonical data or remove a record. A representation that cannot fit the admitted profile returns an actionable 422.

Within each ordered group, use stable sort keys and ID tie-breakers for deterministic reusable-track packing. Expanded nested subtrees reserve complete contiguous track blocks; check every occupied track and descendant footprint. Sort children by canonical order then ID. Parent envelopes may contain their descendants intentionally, never unrelated text. Multi-group rendering requires distinct stable instance keys while canonical counts remain deduplicated. Preserve valid earlier placement only when its predecessor layout is explicitly identified and included in the layout key; otherwise identical inputs must yield identical allocation.

Store ordered logical rows with stable IDs within the layout, variable heights and cumulative vertical offsets. Rows include structural headers and reusable tracks, not one permanent row per canonical record. The manifest returns `totalRows`, `totalHeight`, `detailTotal`, `detailMatchTotal`, `renderInstanceTotal` and group summaries. A group or nested block larger than a page splits at row boundaries, with separately flagged repeated breadcrumbs/parent continuation. Repeated context is not a new record or finding. Zones fill only their scoped visible rows and use identical time boundaries across pages.

The layout request supplies measured `mainBandHeightCss`, fixed reservations for axes, scale/zone labels, navigation and insets, and resulting `availableHeightCss`; validate their agreement against the effective profile. Actual structural rows and repeated continuation headers consume this budget too, without double subtraction. Choose the longest complete row prefix fitting cumulative heights and the row ceiling. A tall first row must use an explicit profile-approved bounded internal-scroll or expanded-label presentation, otherwise return `row_height_limit`; never return an empty successful page that cannot advance. Repeated breadcrumbs must have a bounded presentation. Height changes create a new layout/cursor identity, retain the time map, and reanchor to a stable row/record.

## Cursors and Page Completeness

A row response returns query/snapshot/generation, layout/map/profile IDs, exact `[a,b]` and visible bounds, row ordinal range, heights/budget/reservations, render projections, context, `pageComplete`, and separate payload/next-row continuations. Bind opaque authenticated cursors to scope, generation, query, projection, layout/map/profile, CSS width/height/reservations, row ceiling and next ordinal/fragment. A changed interval, geometry, font, grouping, expansion, camera or profile cannot reuse an old cursor. Response and cache identities include these same inputs.

If a requested row range exceeds record/byte limits, deliver explicitly numbered payload fragments for that same row range. A fragment cursor resumes the unfinished row, not a later time interval. Expose the next vertical page only once the range is complete. The client can display received content as incomplete, but cannot report the row fully loaded or omit remaining members. Cap one logical page at eight fragments; reject excessive expansion before serving its first fragment and recommend a smaller row count or an approved less verbose render profile. If even one row exceeds that bound, return `row_payload_limit`, never skip it. Deterministic layout and projection-size bounds make this exceptional rather than routine.

The paging oracle has five sessions `P01`-`P05`, all overlapping `[10:00,11:00)`, with one profile. Five distinct tracks, ungrouped/header-free, 32 px rows, 64 px data budget and ceiling two yield pages 2/2/1. The union contains five IDs once; window/map/layout identity stays fixed. Nonoverlapping records can share tracks. Also test mixed heights, reservations, oversized rows and stale height cursors.

## Consistency, Caches and Verification

Pinned browsing freezes query, map, rows, overview and counts together until refresh/expiry. Incoming writes produce a notice, not a new density silently paired with old rows. Live mode prepares a replacement snapshot/map/layout and anchor page, then swaps the complete visible artifact set atomically. Coalesce pending commits and maintain at most one replacement in flight. The scale contract's two-second/500-ms-idle geometry schedule and retention rules do not authorize mixed snapshots: retained knots still need a fresh manifest, current density provenance and coherent new rows/counts/overview. Geometry redistribution and data freshness are distinct; retained geometry does not make global row work free. Successful local edits follow the same refresh path. Keep old content marked stale while preparing; preparation failure is an error, not empty results. Preserve drafts and authorized selection; permission revocation invalidates affected handles and clears sensitive cached content immediately.

Server cache keys include authorization scope and every semantic identity above. Disposable caches are in memory or rebuildable ordinary JSON, never a database/search service. Browser data caches are memory-only. ETags for conditional GETs are response-cache validators, not canonical write permissions. Return 400 malformed input, 422 invalid profile/map/range, 413 input size, 429 admission pressure, 409 expired/incompatible cursor or generation, 401/403 authorization failure, and 503 unavailable preparation/storage under the existing disclosure policy. Report snapshot expiry even after a previously successful page; never restart pagination invisibly.

Future verification must cover: full-filter density against an independent interval sweep; hidden-page records changing density; exact C/M counts; long/ongoing/zero-duration edges; inverse/forward maps and half-open boundaries; 2/2/1 paging and oversized fragments; group/nesting continuation; malicious cursors; font readiness and real projected rectangles; zones crossing knots/pages; concurrent writes, expiry, restore and revocation; and bounded browser/network memory without full-list prefetch. These tests are specified, not run.

Retain warm row-query p95 300 ms and the existing one-second p95 full live-display target for Uniform/warm trivial updates as separate measurements. For full Adaptive recomputation, propose notice/stale indication p95 within one second, warm coherent-bundle replacement p95 within three seconds after eligible idle, and cold preparation p95 within ten seconds for the 100,000-record reference fixture. Provide bounded 202 progress and overview/status within three seconds of initial navigation, but do not call that an interactive complete detail view. These are new proposed targets, not measured results. Measure admission failures, unique-font/label cold cost, memory, payloads and atomic replacement latency; report failures rather than assuming retained geometry or existing linear-mode benchmarks cover global adaptive work.
