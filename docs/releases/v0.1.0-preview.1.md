# OpenBEXI Timeline 0.1.0 Preview 1

First packaged development preview. This is not a stable or production-qualified release.

## Included

- Orthographic Three.js timeline, synchronized overview, colored zones, measured labels, and vertical row pagination.
- Adaptive/local magnification, manual scale controls, momentum navigation, calendar, search, descriptors, and Timeline/Table/Split views.
- Complete offline dataset library: default dataset, ephemeris, JFK, Monet, religions, and space exploration; 2,349 records total.
- Read-only JSON archive browsing with multiple paths, namespace grouping, favorites, day partitions, and on-demand loading.
- Separate Python JSON-file workspace APIs and shared Local/Server contracts for records and configuration.
- Offline help, visual-model controls, PNG export, snapshot export, screenshots, and operational documentation.

## Download

The standalone ZIP contains `index.html`, offline instructions, release notes,
data notices, and runtime dependency notices. A project `LICENSE` is included
only after the owner selects one. Verify the ZIP with the accompanying
`SHA256SUMS` and inspect `release-manifest.json` for the source commit and hashes.
These artifacts do not include the Python interpreter or a running server.

## Known Limitations

- Full legacy compatibility, accessibility, performance budgets, and production hardening are not yet certified.
- Local imports are limited to 25,000 records / 64 MiB. Oversized inputs are rejected, not truncated.
- Local edits require explicit export; they do not synchronize automatically or constitute a server backup.
- Writable server storage supports one writer process on local disk, not multiple workers or shared network storage.
- Some historical dates and artwork remain uncertain or unavailable. Reference-based screenshots are not pixel-equivalence evidence.
- Source licensing and historical-data/image redistribution need owner review before a public release or demo. Existing GPL legacy-asset notices remain intact.

## Verification Policy

The publication workflow requires the full candidate matrix and standalone browser
checks before creating a GitHub prerelease. It never promotes this preview to
"Latest" automatically. Skipped or failed qualification checks must remain visible.
Local measurements and test counts are recorded separately in the repository's
verification documentation; these release notes do not invent a completed remote run.
